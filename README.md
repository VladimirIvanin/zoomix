# Zoomix

Увеличение фотографий товара внутри кадра (`inner`), в боковом окне (`side`) или в круглой лупе (`lens`). TypeScript, без зависимостей во время выполнения. По умолчанию — `inner` и увеличение до 2×. Доступное разрешение оригинала ограничивает кратность.

## Демо

Требуется Node.js 22.12+ и npm. Из корня репозитория:

```sh
npm ci
npm run build
npm run dev
```

По адресу, который выведет Vite, доступны страницы:

- `/docs/` — документация: подключение, параметры, методы и интеграция с галереями.
- `/examples/` — демо с переключением трёх режимов увеличения.
- `/examples/sliders.html` — рабочие примеры со Splide, Swiper и tvist.

HTML-страницы находятся в каталогах `docs/` и `examples/`; в корне проекта `index.html` нет.

## Подключение в HTML

Скопируйте `dist/zoomix.min.js` и `dist/zoomix.css` в каталог ресурсов темы.

```html
<link rel="stylesheet" href="/assets/zoomix.css">
<script defer src="/assets/zoomix.min.js"></script>

<div data-zoomix="side" data-zoom-scale="2.5">
  <img src="/products/watch-640.jpg" data-zoom-src="/products/watch-2400.jpg"
       width="640" height="480" alt="Циферблат часов" draggable="false">
</div>
```

Обёртка должна содержать одну фотографию. Можно использовать `picture`, `srcset`, `object-fit` и `object-position`. Размер превью задаёт тема магазина. Для большого оригинала используйте тот же кадр и пропорции. Без `data-zoom-src` или при ошибке загрузки Zoomix берёт выбранный браузером источник превью. Если пикселей для увеличения недостаточно, остаётся обычная фотография.

Браузерная сборка создаёт экземпляры для существующих и добавленных `[data-zoomix]`, освобождает их при удалении из DOM и предоставляет `window.Zoomix`. Настройки конкретного экземпляра передавайте при первом создании. Для произвольной JS-настройки в браузерной сборке используйте обёртку без атрибута автоматической инициализации.

## ESM и TypeScript

Для установки собранной локальной версии выполните `npm pack` в этом репозитории, затем `npm install /путь/к/zoomix-0.1.0.tgz` в проекте магазина.

```ts
import Zoomix from 'zoomix';
import 'zoomix/style.css';

const photo = document.querySelector<HTMLElement>('#product-photo')!;
const zoom = new Zoomix(photo, {
  mode: 'side',
  scale: 2,
  sideTarget: document.querySelector<HTMLElement>('#detail-panel') ?? undefined,
});

// Перед сменой слайда
zoom.close();

// После ручного обновления вёрстки
zoom.refresh();

// При размонтировании компонента
zoom.destroy();
```

ESM оставляет инициализацию приложению. Повторный конструктор для той же обёртки возвращает существующий экземпляр. Изменения источника и замена фотографии внутри обёртки отслеживаются автоматически.

Укажите размеры панели `sideTarget` в CSS. Без неё окно появляется справа или слева от фото и следует за ним при прокрутке. При нехватке места включается `inner`.

Пропорции бокового окна увеличения задаёт `sideAspectRatio`. Укажите число: желаемую ширину окна разделите на высоту. Например, `1` — квадрат, `1.5` — окно в полтора раза шире своей высоты, `0.75` — вертикальное окно с пропорциями 3:4. Параметр задаёт пропорции, а размер в пикселях рассчитывается автоматически.

```js
zoom.update({ sideAspectRatio: 1 });     // Квадрат
zoom.update({ sideAspectRatio: 4 / 3 }); // Горизонтальное окно
zoom.update({ sideAspectRatio: 3 / 4 }); // Вертикальное окно
zoom.update({ sideAspectRatio: null }); // Вернуться к HTML-атрибуту или автоматическому размеру
```

В JavaScript можно написать `4 / 3`: JavaScript сам выполнит деление. В HTML укажите результат деления с десятичной точкой: `data-zoom-side-aspect-ratio="1.333333"` на обёртке. Запись `"4 / 3"` в HTML-атрибуте не поддерживается. JS-настройка имеет приоритет. Допустимо любое положительное конечное число; некорректное значение даёт автоматический размер. Окно вписывается в `sideTarget` с сохранением пропорций и выравнивается по его левому верхнему углу. Без `sideTarget` оно вписывается в размер превью и высоту экрана. Размер также ограничен увеличенным изображением. Если параметр не задан, размер окна определяется автоматически. Настройка применяется только к `side`; рамка на фото показывает фрагмент, видимый в окне увеличения, и обрезается по видимой части превью.

Размер и обводку лупы можно задать на обёртке:

```css
.product-photo {
  --zoomix-lens-size: 160px;
  --zoomix-lens-outline: 2px solid #fafafa;
}
```

## Управление

| Ввод | Действие |
| --- | --- |
| Мышь | Навести для увеличения, перемещать для осмотра, увести для закрытия. Колесо прокручивает страницу. |
| Сенсорный экран | Тап открывает увеличение внутри кадра. Следующим жестом перемещают фото, повторным тапом закрывают. При закрытом зуме работают свайпы галереи и прокрутка страницы. |
| Клавиатура | Перейти к фото через Tab. Enter или пробел переключают увеличение, стрелки перемещают фрагмент, Escape закрывает. |

При наведении клик мышью сохраняет увеличение. Для переключения зума кликом задайте `zoomOn: 'click'` (по умолчанию `'hover'`) или HTML-атрибут `data-zoom-on="click"` на обёртке:

```html
<div data-zoomix="inner" data-zoom-on="click">
  <img src="/products/watch-2400.jpg" width="640" height="480" alt="Часы">
</div>
```

```js
zoom.update({ zoomOn: 'click' });
```

В режиме `click` левая кнопка открывает увеличение, повторный клик, Escape или уход курсора закрывают. Перемещение курсора осматривает фото, но само не открывает зум; перетаскивание не считается кликом. JS-настройка имеет приоритет над атрибутом. Смена `zoomOn` через `update()` закрывает текущий зум мыши. Касания и клавиатура работают одинаково при обоих значениях.

## Галереи и проверки

Полный пример подключения каждой галереи находится в `examples/sliders.js`. Каждая получает экземпляр на обёртку изображения в слайде, включая копии в loop-режиме. При начале перехода пример вызывает `close()`, а при изменении набора слайдов подключает новые обёртки и освобождает удалённые.

| Галерея | Исключение активной поверхности из перетаскивания |
| --- | --- |
| Splide 4 | `noDrag: '.zoomix-touch, .zoomix-touch *'` |
| Swiper 14 | `noSwipingSelector: '.zoomix-touch'` |
| tvist 1 | Добавить `.zoomix-touch *` к `focusableElements`. |

```sh
npx playwright install chromium webkit firefox
npm test
```

Сборка проверяет типы и gzip-бюджеты в 8 КиБ для каждой JS-сборки и 2 КиБ для CSS. Проверка пакета устанавливает tarball в отдельный временный проект без сети и проверяет ESM-импорт без DOM, exports и TypeScript потребителя.

Playwright проверяет растровые изображения, `picture/srcset` и DPR, геометрию, CSS темы, клавиатуру, отмену и ошибки загрузки, клонирование и удаление экземпляров, общий `sideTarget`, loop-режим и добавление слайдов. Настольные сценарии выполняются в Chromium, WebKit и Firefox. В Chromium последовательности сенсорных жестов, multi-touch и потеря pointer capture проверяются через CDP; в WebKit выполняются касания через Playwright. Мобильные сценарии не запускаются в Firefox; три CDP-проверки пропускаются в WebKit.

Для проверки на устройстве запустите `npm run dev -- --host 0.0.0.0` и откройте сетевой адрес в Safari на iPhone и в Chrome на Android. В каждой галерее проверьте свайп, тап, перемещение увеличенного кадра, повторный тап, затем свайп и вертикальную прокрутку.

## Экземпляры и группы

`Zoomix.get(element)` / `Zoomix.getScope(root)` получают существующий объект без создания. Повторный конструктор и `mount()` возвращают прежний объект, настройки меняются явно через `update(patch)`.

```js
const scope = Zoomix.mount(widgetRoot, {
  selector: '.js-product-zoom',
  options: element => ({ mode: 'side', scale: 2,
    sideTarget: widgetRoot.querySelector('.zoom-panel') })
});
const zoom = Zoomix.get(widgetRoot.querySelector('.js-product-zoom'));
zoom.open(); // По центру, без переноса фокуса
zoom.update({ mode: 'lens', scale: 3, sideTarget: null });
scope.disable(); // Закрывает и блокирует все способы открытия
scope.enable();
scope.close(); // Перед сменой слайда
scope.refresh(); // После ручной перестройки галереи
scope.destroy(); // До удаления владельца
```

Управляемые фото используют свой селектор **без `data-zoomix`**. Пересекающееся владение и смешивание автоматического режима с группой на одной фотографии считаются ошибкой конфигурации. Автоматические фотографии и независимые управляемые группы поддерживаются на одной странице.

Группа автоматически подключает новые фото и освобождает удалённые. Перенос внутри группы сохраняет экземпляр; перенос между группами создаёт новый с настройками нового владельца. Скрытие сохраняет группу. Один общий наблюдатель DOM на документ страхует удаление групп без явного cleanup. Для одиночного ручного ESM-экземпляра destroy вызывает владелец.

`scope.getInstances()` возвращает новый массив. Методы группы: `refresh`, `update`, `close`, `enable`, `disable`, `destroy`, `on`; свойства: `element`, `signal`. `scope.update(patch)` применяется к текущим и будущим фото поверх `options`. Индивидуальный `zoom.update()` изменяет текущую фотографию. `refresh()` не переисполняет функцию настроек для существующих фото. `sideTarget: null` освобождает прежнюю панель. Повторный destroy и команды уничтоженного объекта безопасны.

```js
const off = scope.on('open', event => {
  console.log(event.instance, event.element, event.state);
}, { once: true, signal: externalController.signal });
off(); // Ручная отписка
const state = zoom.getState();
```

События фото: `statechange`, `open`, `close`, `loadstart`, `load`, `error`, `destroy`. Группа пересылает их с `scope` и `instance`, включая будущие фотографии, и добавляет `mount` / `unmount`. Собственное событие `destroy` группы не содержит `instance`. При освобождении фото сначала приходит его `destroy`, затем `unmount`; собственный `destroy` группы приходит последним. Сигнал группы прерывается перед освобождением фото, сигнал фото — перед его окончательными `statechange` / `destroy`.

`getState()` возвращает снимок: `enabled`, `active` (запрошено открытие), `visible`, `loading`, `destroyed`, `mode`, `zoomOn`, `scale`, `effectiveMode`, `effectiveScale`. Фактические режим и масштаб равны `null`, когда увеличение скрыто. `open` приходит после появления слоя, `close` — после скрытия ранее видимого слоя. Отмена ожидающего открытия меняет active без ложного close. Загрузка после close может сохранить изображение в кеше, но не открывает его повторно.

Сначала приходит `statechange`, затем соответствующее событие. Подписка не воспроизводит историю; движения указателя не порождают события без изменения состояния. Исключение обработчика записывается в консоль и не прерывает очистку и остальные подписки.

События загрузки содержат `source`, `requestedSource`, `fallback`. Ошибка оригинала публикует `error`; `fallback: true` означает попытку загрузить превью. Успешный fallback публикует `load`, ошибка превью — ещё один `error`. Устаревшие ответы после смены источника или уничтожения игнорируются.

Примеры InSales: [examples/insales.js](examples/insales.js). Внешние подписки привязывайте к `scope.signal`, чтобы автоматическое уничтожение группы снимало и их. Настоящая витрина и редактор требуют отдельной интеграционной проверки.

## Публикация

npm-публикация запускается при публикации GitHub Release с тегом `vX.Y.Z`. К релизу прикладываются браузерные JS, CSS, gzip и npm-архив; тот же архив отправляется в npm через Trusted Publishing. GitHub Pages собирается отдельно для `/zoomix/`.

После первого выпуска установка: `npm install zoomix`. CDN:

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/zoomix@0.1.0/browser-build/zoomix.css">
<script defer src="https://cdn.jsdelivr.net/npm/zoomix@0.1.0/browser-build/zoomix.min.js"></script>
```

Используйте одинаковую точную версию JS и CSS. Эти URL начнут работать после публикации соответствующей версии в npm. Однократная настройка npm/GitHub Pages и порядок выпусков: [RELEASING.md](RELEASING.md).
